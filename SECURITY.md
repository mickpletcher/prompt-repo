# Security Policy

## Supported content

Security fixes are applied to the latest content on the default branch. This
repository does not currently publish versioned software releases.

## Report a vulnerability privately

Do not open a public issue for credentials, private data, exploitable prompt
behavior, or a vulnerability that has not been disclosed responsibly.

Use GitHub's **Report a vulnerability** option on the repository's Security tab
to submit a private report. Include:

- the affected file and section
- the commit or link where the issue appears
- the security impact and realistic abuse case
- reproduction steps, when applicable
- a suggested correction, if known

If private vulnerability reporting is not available, use a private contact
method listed on the maintainer's [GitHub profile](https://github.com/mickpletcher)
without including sensitive details in a public message.

## Relevant security concerns

Examples include:

- exposed credentials, tokens, personal data, or private endpoints
- instructions that bypass approval for destructive or irreversible actions
- prompt-injection content presented as trusted project instructions
- unsafe workflow permissions or unpinned third-party automation
- links or downloads that introduce a credible supply-chain risk

General wording improvements and non-sensitive content errors belong in a
regular issue.

## Disclosure

Allow the maintainer a reasonable opportunity to investigate and correct a
confirmed issue before publishing technical details.
